A Matrix feature crosses protocol, capability, presentation, and often encryption boundaries. Keep each concern with its owner.

## Start from the protocol behavior {#protocol-behavior}

Identify the Matrix event, state key, endpoint, account scope, room scope, permissions, and encryption implications. Check the installed `matrix-js-sdk` types and implementation before assuming an API or event order.

Choose the owning data-access capability. Add a stable Trinity model and command there, and export only that public contract. Feature components consume it without importing the SDK.

## Project authoritative events {#project-events}

Attach only the SDK events that invalidate the read model and reconcile from the supplied client. Keep the projection tied to the exact account or conversation lifetime. Define what happens on client replacement, soft logout, sync reset, room change, and release.

Commands remain cold and finite. Preserve local echo only where the product explicitly needs it; otherwise allow SDK events to publish the accepted result.

## Render formatted messages {#formatted-messages}

`formatted_body` is sender-controlled HTML. `sanitizeMatrixHtml` in `@trinity/util/matrix` scrubs it once against the Matrix allowlist and then runs render-only passes whose output is memoized per body, so nothing that depends on the viewer, the theme or the platform may enter that string. `MatrixHtmlDirective` in the Rooms feature binds the result with `[innerHTML]`, where Angular's sanitizer runs again, and composes the leaf directives that need the live DOM. Data Angular strips at that leaf (`data-*`, `style`) travels as a class token or an inert attribute Angular keeps, or is re-read from the sanitized string by parsing it once and pairing marked elements in document order. `sanitizeOutgoingHtml` shares the allowlist but none of the render-only passes.

### Links {#message-links}

The render pass gives `http(s)` links `target="_blank"` and `rel="noopener noreferrer"`, and so does the linkified plain-text body, so a middle-click, a modifier-click or a context-menu open behaves like a plain click. `matrix.to` and `matrix:` links get neither and stay routed in Trinity by `MatrixLinkDirective`, and a sender's own `target` and `rel` never survive the allowlist. A plain click still goes through `window.open(…, 'noopener,noreferrer')`, which Electron hands to the system browser. On Capacitor, `e2e/mobile/specs/message-links.e2e.mts` checks that a message link leaves the WebView. On iOS the WebView hands the link to the system browser; Android does too.

A link to a user renders as a mention pill. Its text is the user's room display name, or their Matrix ID when the room has none, and its `title` is the Matrix ID; the sender's link text is never shown, so a pill cannot name one person while linking to another. The normalizer resolves the names, and `collectMessageSenders` counts the linked users so a late profile re-renders the pill.

### Allowed HTML, colours and spoiler reasons {#message-html-fidelity}

The allowlist follows Matrix spec v1.19. It adds `s` and `data-mx-maths`, enforces each attribute on its own tag in the shared DOMPurify hook, drops `name` and any `title` outside `img`, keeps `class` only as `language-*` on `code`, and flattens anything nested more than 100 deep to its text. `color` and `start` are URI-safe for DOMPurify, because the allowlist's URI pattern would otherwise reject their values. The spec's `width` and `height` on `img` are allowed because inline images are capped in height (see [Inline images](#inline-images)), so a sender cannot open an arbitrarily tall empty box. `font` and `strike` are still read; `sanitizeOutgoingHtml` unwraps `font` and sends `strike` as `del`.

Sender colours are accepted only as `#RRGGBB`. The render pass turns `data-mx-color`, `data-mx-bg-color` and a `font`'s `color` into `mx-fg-rrggbb` and `mx-bg-rrggbb` class tokens and removes `color`, so nothing unchecked is painted. `SenderColoursDirective` resolves the body's `--trinity-message-surface` (the workspace pane in the timeline and thread, set by the composer preview and edit history for their own surfaces, the canvas only as a fallback), its text colour, `--trinity-link` and `--trinity-rail` to sRGB, and keeps a colour only if it reaches 3:1 by WCAG 2 relative luminance against what it is drawn on: a text colour against the nearest kept sender background or the surface, a background against the inherited text colour, and a pair against each other before the background is checked alone. Links and table headers change that context: text inside a link is the link colour, so a kept background that holds a link must also read with it, and a table header draws on the rail, so a kept text colour that holds one must also read on the rail. If a value cannot be resolved, nothing is painted. It reads computed style once per body, re-checks every mounted body when the root's `dark` class or `data-theme` changes, and never colours code, mention pills or the spoiler element itself.

A spoiler's reason loses control and bidi formatting characters, is trimmed, collapsed to one line, cut to 80 characters and copied into `label`, which Angular keeps; CSS shows it, isolated, as generated content on the concealed bar. A concealed spoiler is a button named `Spoiler: <reason>, activate to reveal` (or `Spoiler, activate to reveal`). Revealing it removes that name and role at once, and its tab stop when it next loses focus, so keyboard focus is never dropped.

### Inline images {#inline-images}

Only `mxc://` image sources survive the allowlist hook; any other `img`, including `data:` and `blob:`, becomes its alt text, or "Image" without one. The render pass moves a valid source to `data-mx-src`, which Angular strips at the leaf, so the browser never sees an `mxc:` URL. It marks the first 10 non-emoji images in a message `mx-image` and turns the rest into alt text; emoji keep their own cap of 50. `InlineMxcImagesDirective` re-reads the sources from the sanitized string and resolves each image through authenticated media (`MediaService.resolveMedia(…, 'thumbnail')`) only once it comes within one viewport of its scroller, through one shared `IntersectionObserver` per scroll root, and only after a concealed spoiler around it is revealed; until then the image is hidden from assistive technology and out of the tab order, and activating it opens nothing. Images are at most 300px tall and the body's width: `--trinity-message-image-max-height` on `img.mx-image` in `rendered-markdown.scss` is the one source of that cap, and the box a sender's `width` and `height` reserve (kept only as integers from 1 to 10,000, in `inline-image-box.ts`) reads it too. Until its thumbnail arrives, an image shows an inline transparent placeholder (never fetched, never pinned) in a box with the control border, so no broken-image icon shows and the box stays visible in forced-colors mode. An image inside a concealed spoiler takes no space until the spoiler is revealed; a spoiler holding nothing but images still draws a bar, labelled "Spoiler" when it has no reason, one nested spoiler at a time. Click, Enter or Space opens the full image through `MediaViewerLauncher`, the lightbox launcher `MediaAttachmentComponent` also uses; the launcher drops the full image from the media cache when the viewer closes. An image inside a link follows the link instead. A failed image becomes its alt text. Inline images are not encrypted, even in an encrypted room: that is how the sender sent them.

### Maths {#message-maths}

The render pass marks `span[data-mx-maths]` and `div[data-mx-maths]` (inline and display maths, Matrix spec v1.11) with `mx-maths`; the sender's fallback shows until KaTeX loads. `MathsDirective`, through the root `MathsLoader`, loads `maths-render.ts`, a lazy chunk wrapping KaTeX `version:katex`, and the non-injected `katex.css` bundle the first time a rendered body contains maths, then renders each expression from the LaTeX it re-reads in the sanitized string with `trust: false`, `maxSize: 10`, `maxExpand: 100`, `strict: 'ignore'` and a fresh macro table per expression. KaTeX's output is the one markup in a message that skips Angular's sanitizer, so it first passes a separate, maths-only DOMPurify instance (HTML, MathML and only the `svg`, `path` and `line` elements KaTeX draws; no script, `foreignObject`, event handlers, links, images, URL attributes or `style` URLs). Errors, expressions over 2,000 characters and every expression past the 50th in a message show their LaTeX as code. An image inside a maths fallback becomes its alt text in the render pass, so KaTeX replacing the fallback cannot shift which inline image gets which source. KaTeX's MathML is kept for screen readers and its visual HTML is `aria-hidden`. `katex.css` joins the `vendor` cascade layer, where it also undoes KaTeX's `body { position: relative }`, and its fonts are served from the app's own origin.

Anything KaTeX draws in its error colour, such as an unknown command or one that `trust: false` blocks, counts as an error and shows its LaTeX. Maths keeps the body text colour: `\color`, `\textcolor`, `\colorbox` and `\fcolorbox` render their content without a colour, `SenderColoursDirective` paints nothing on or inside `.mx-maths`, and `rendered-markdown.scss` resets `.mx-maths` to `--trinity-text` so it does not inherit a sender colour painted around it; inside a link it takes the link colour. In forced-colors mode maths keeps its own colours, set to the system text and link colours, so `\phantom`'s transparent content stays invisible and no text backplate covers the limits under a `\sum`.

Maths never draws outside its message body. KaTeX's `maxSize` caps only positive sizes, so an expression whose markup moves content sideways more than 10em (a `left` or margin that long, such as a large negative kern), up or down more than 50em (a `top`, `bottom`, `vertical-align` or negative `height` that long), or holds any other negative length past 10em shows its LaTeX. Tall `cases`, `aligned` blocks and matrices place their rows well past 10em and render; a box's own positive height or width only makes the formula bigger. Within those bounds, `rendered-markdown.scss` clips a display formula to its box and each inline KaTeX run (`.katex-base`) to its own box grown by 1em (`clip-path: inset(-1em)`, so glyphs and `\mathllap` that overhang a little keep their pixels and no layout or baseline changes, in WebKit too). Moves that add up can still make one run far wider than the body, and a raise or a drop reaches above or below it, so the body itself (`.msg__text--html`) is an overflow clip on every side, its edge a focus ring's reach (2px plus a 2px offset) out from its content: nothing a sender writes covers or takes the clicks of the authenticity shield, avatar, name, timestamp, "(edited)", reactions or toolbar, and no positioned run gives the timeline, a thread or the composer preview a scroll range. WebKit cannot widen an overflow clip (`overflow-clip-margin`), so `message-row` and `edit-history` pad the body by that reach and take it back with a negative margin, sideways and below, and above in a grouped row (a first row keeps its top margin, so a ring flush with its top edge can lose a pixel or two there in WebKit). Real content grows the lines it sits on, so only overhang that takes no room is cut. Ordered-list numbers would hang past that clip, so the render pass marks lists by their longest number: two characters (`mx-ol-wide`) get a wider indent, longer ones (`mx-ol-long`, such as a sender's `start="100000"`) sit inside their items.

Inline maths with a run wider than the body (KaTeX never wraps inside a run) scrolls sideways on its own: `MathsDirective` marks it `mx-maths--wide` whenever one of its runs is wider than the body's content box, re-checked through one `ResizeObserver` per body with maths, and the stylesheet makes it an inline-block scroller as wide as the body, as display maths, tables and code are. A display formula's `\tag` is laid out after the formula rather than pinned to the visible right edge, so it scrolls with a wide formula instead of covering it; the rule uses `:has()`, so on Firefox 119 and 120 the tag keeps KaTeX's own placement.

Production builds name their lazy chunks (`namedChunks`), so the service worker's lazy `maths` asset group in `ngsw-config.json` caches the chunk and `katex.css` only once a message has shown maths online. KaTeX's fonts are in no group, so maths shown offline uses fallback fonts, and a message seen offline before KaTeX ever loaded keeps the sender's fallback.

### Long messages {#show-more}

A timeline or thread body, text or caption, formatted or plain, sits in a `.msg__clamp` wrapper capped at 24 lines of the message type. `BodyOverflowObserver`, one per list, watches each body with one `ResizeObserver` and compares its content-box height from the observer entry (so a formatted body's focus-ring padding is not counted; `scrollHeight` only where an entry carries no size) with the 24-line limit inside the callback, writing one signal per row. A row's signal lives only while the row reads it or its body is observed, so the list keeps as many as it renders; past that, only the ids of rows measured long are remembered (up to 500, until the list moves to another room or closes), so a long row scrolled back into view starts collapsed. A longer body collapses to 20 lines behind a fade and gets a Show more button with `aria-expanded` and `aria-controls`, and a body of 21 to 24 lines is shown whole. The expanded rows live in `ExpandedBodiesStore`, provided by the rooms page, shared by the timeline and the thread view, and reset when the selected account or room changes. An explicit jump target (a reply, permalink, search hit, pinned message or notification) is expanded before the list scrolls to it; the unread position expands nothing. The composer preview, edit history, reply previews and search snippets are never clamped, and there is no transition, so reduced motion needs no special case.

The clamp rules live in `rendered-markdown.scss`, not the row's stylesheet, which is at its component style budget. The 24-line cap allows 1em plus `--trinity-space-3` beyond the lines for the margins that collapse out of a body (a first heading's top, a last rule's or list's bottom), which the content box does not include, so a body measured at 24 lines or fewer is never cut. They clip only the block axis with `overflow: visible clip`, so the wrapper is never a scroll container, and a ring-sized block padding (taken back by a negative margin) keeps the focus rings of links on a body's first and last lines whole. A body that grows after it was measured, such as one whose inline image loads or whose maths renders, is measured again and can gain the button. Keyboard focus (`:focus-visible`) moving into a collapsed body expands it; the timeline brings the focused control into view after its own scroll correction for the taller row, and the thread view once the reply has rendered. A mouse click does not expand, so the link under the pointer does not move. A reader at the very bottom of the timeline stays there when a message grows or a new one arrives, even while the anchor kept for loading older history is still active. A jump target taller than the list is aligned by its top rather than centred, and a recent jump is aimed again after the older history it fetched lands. The timeline and thread scrollers reserve their scrollbar gutter (`scrollbar-gutter: stable`), so collapsing a body never toggles a classic scrollbar and rewraps the bodies.

## Prove protocol and presentation {#prove-feature}

Unit-test normalization, permissions, account isolation, cancellation, errors, and cleanup. Add a disposable-homeserver journey when interoperability, federation-independent server state, encryption, multiple clients, or event ordering is part of the claim. Add browser evidence for the user-visible flow.

Never place real tokens, recovery keys, server databases, or private room content in fixtures or diagnostics. Test accounts and homeservers belong to the suite that creates and destroys them.
